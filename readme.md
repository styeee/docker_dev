## Структура:

src - исходные файлы и инструкции сборки
build - артефакты сборки
test - тесты на pytest
work - рабочий каталог

## Контейнеры:

### builder - сборка
Производит сборку через cmake на основе файлов содержащихся в src.
Использует *.h *.cpp CMakeLists.txt ...
Промежуточные файлы сохраняются в build (для удобной пересборки).
В папку work сохраняются результаты сборки (описанные в install).
В контейнере предустановлена библиотека luajit получение через find_package(LuaJIT).
В контейнере предустановлена библиотека asio получение через find_package(asio).

### tester - тестирование
Производит тестирование через pytest.
Файлы описывающие тесты содержатся в tests и имеют вид *_test.py.
Внутри файлов описаны функции с постфиксом _test.
Они должны тестировать бинарники содержащиеся в work.
Также доступен к использованию модуль pexpect.

### runner - запуск
Запускает luajit удаленный интерпретатор создающий песочницу.
Интерпретатор имеет доступ к бинарникам из work.
Можно запускать скомпилированные программы из lua через os.execute.
Также можно запускать функции описанные на СИ через ffi.
Можно запускать функции из динамических библиотек с префиксом luaopen_.
Доступ организован через TCP порт 55555.
При необходимости порт можно поменять через переменную среды $port.

## Эксплуатация:

### Общее
start.sh содержит список всех необходимых для работы действий.
Например, в нем можно собрать или запустить контейнер.
Все контейнеры при сборке берут за основу по умолчанию debian:12-slim.
При необходимости основу можно поменять через переменную среды $BASE.
В папке _images описаны докер контейнеры.
В папке _actions описаны действия в виде bash скриптов.

### Сборка
Перед сборкой необходимо создать CMakeLists.txt в папку src.
В CMakeLists.txt указать cmake_minimum_required(VERSION 3.22).
Описать цели сборки через add_executable, add_library ...
Описать прочие действия сборки...
В конце обязательно описать деплой результатов в work...
Например, install(<targets> ... DESTINATION work).
Рядом нужно поместить необходимые файлы с кодом на C/C++.
Результаты сохранятся в work, а промежуточные файлы в build.

### Тестирование
Тестирование необходимо проводить после сборки.
На этапе сборки также могут присутвовать white-box тесты.
На этом этапе могут присутствовать black-box тесты.
В папке test нужно поместить файлы с тестами *_test.py.
Тесты описываются функциями с постфиксом _test.
При написании тестов используется pexpect и assert.
Тестирование проводится через pytest, результаты видно в консоле.

### Запуск
Осуществлять запуск необходимо после сборки.
При запуске включается удаленный интерпретатор luajit.
Подключиться можно через ncat 127.0.0.1 55555.
luajit имеет доступ к бинарникам из work.
Если в work есть файл init.lua, он запустится первым.
Чтобы остановить сессию нужно использовать os.exit.
